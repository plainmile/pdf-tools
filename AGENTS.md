# PDF Tools Agent Instructions

- The product lives at `pdf.plainmile.com` and in a separate `plainmile/pdf-tools` repository. Never edit the existing paycheck site's code or CI as part of the PDF work.
- All PDF processing is in-browser; never upload, log, store or transmit files, filenames, extracted text, or generated PDF content.
- Self-hosted LAN users may open the site over HTTP on a private IP, where `crypto.randomUUID` is not exposed; use `getRandomValues` for temporary IDs as a fallback. Do not mistake HTTP compatibility for public-network security.
- The site is a bilingual English / Simplified Chinese, privacy-first Astro + React static app with no user account or server-side PDF service. Public URLs are `/` and `/zh/` with parallel routes. English and Chinese content must be human-readable, not browser auto-translation.
- Deploy via a Docker-built static site served by Nginx. No host-installed Node/npm. Keep the shared `edge` Docker network and preserve existing website routing.
- netcup Compose files for this service must live in `/opt/compose/pdf-tools/` (production `compose.prod.yaml` and `.env`). All other Compose apps on this VPS follow `/opt/compose/<service>/`. Never reintroduce `/opt/data/compose/pdf-tools` as the working/deploy directory; reference the legacy path only for one-time, non-destructive migration if the target is absent. Put separately maintained operational scripts under `/opt/data/scripts/<purpose>/`, not in a Compose directory.
- The PDF.js Worker has an unversioned public path; keep it revalidated (`Cache-Control: no-cache`) on every deployment, while preserving asset caching for hashed JS chunks. CI must check MIME type and cache headers to prevent client/Worker version mismatch.
- Use feature branches + PRs + CI. Never bypass main protection or merge while unit/build/E2E tests are failing.
- Verify actual exported PDF pages using pdf-lib in E2E after drag, rotation, deletion, selection and splitting.
- Source-file grouping is strictly a view mode, not a document operation. Always retain real export indices and avoid silently grouping/reordering page references. Group selection and collapsing must not commit history edits. Test interleaved files and Chinese 375 px mobile, and run 360-page desktop/mobile lazy-canvas and Chromium JS-heap diagnostics (not a claim of native peak memory safety).\n- Duplicate selected pages adjacent to their originals, with distinct new page IDs and preserved rotation/source references. Blank insertions must match a chosen page's visible dimensions and honor the 600-page/200MiB limits. Generated blanks must not consume the 20 actual imported-file slots. Both actions must be Undo/Redo safe and E2E must inspect real PDF output and ordering. UI-only success indicators are insufficient.
- All indexable public pages must have unique localized titles/descriptions, canonical URLs, reciprocal hreflang `en`/`zh-CN`, meaningful prerendered content, internal links and inclusion in sitemap. The 404 page must return status 404 and be excluded from indexing.
- For the real nonindexable bilingual 404 page, do not emit canonical URLs, hreflang peers, or a language-switch link to a nonexistent `/zh/404/`. It must return HTTP 404 with a noindex directive and a useful home link. The same full public SEO regression must verify all 36 localized indexable routes for unique titles/descriptions, canonical + reciprocal hreflang, accurate WebSite/WebApplication/BreadcrumbList JSON-LD, complete sitemap, and valid on-site navigation targets; never add misleading schema or keyword stuffing.
- Keep limits on document count, file size, total pages and image pixel count. Passworded, malformed PDFs and browser resource exhaustion must fail safely with user-friendly messages.
- Never claim a document is securely redacted or digitally signed if it is only visually overlaid.
- Appearance must support follow-system, light, and dark, with restrained professional office-app styling and enough contrast; do not introduce AI-style landing-page gradients or meaningless decoration.
- Do not add OAuth, ad code, telemetry, remote fonts, third-party upload APIs or paid AI without explicit approval and privacy review.
- Production container must not bind ports 80 or 443 on the host. Domain and TLS changes require testing edge proxy config and preserving current routes.
- The remote repository and DNS/Nginx have been created by the user. Never present a branch/PR or published image as proof of a deployed and browser-tested production site.
- Long PDF exports need cooperative cancellation and visible page progress; aborted exports must never download partial files. Setting fit-to-image must clear any hidden crop/cover option, and image-page layout must be initialized from active images, not stale Undo-only sources. Show advanced PDF feature-loss warnings only when the active workspace contains an original PDF.

- Warn before navigation would discard unsaved in-browser PDF/photo/text work. Same-tab tool/language links should use an accessible localized confirmation; browser Reload/Back/Close use native beforeunload where supported. Downloads and links that open a separate tab must not be blocked. After full export without further edits, normal navigation should work. Never persist document contents to browser storage or server to implement this warning.
- Clearing imported pages/sources/history is irreversible; display a bilingual inline confirmation with an option to keep editing. Do not make a one-click clear discard previous page ordering and Undo/Redo.
- The 200 MiB workspace budget must account for actual retained source byte buffers: original photo bytes PLUS its converted PDF, PDF-only sources once, and generated blank PDFs. Never equate the compressed upload size with retained memory. Import and image reflow checks must be atomic; always test real WebP imports and large theoretical retention budgets. The bound excludes temporary canvas/PDF.js/export allocations and must not be advertised as guaranteed peak memory.\n- Newly authored PDFs (workspace page composition, raster compression and TXT/Markdown-to-PDF) must not stamp a PlainMile title/creator, default library Producer, or automatic creation/modification timestamps. Keep pristine PDF bytes unchanged. Test actual exported PDF properties; this is not a full metadata scrubber or secure redaction feature.
- Text watermarks must be opt-in and off by default, including after clearing the workspace. Never insert a branded watermark automatically. Treat them as visual marks, not redactions. All operations remain browser-local and must work for CJK text where system fonts are present.

## CI, release and resource budget

- Every PR update and every main commit must pass unit/build and full Playwright E2E against the built production Docker image. Feature commits are tested through the PR, not a simultaneous push run: duplicate same-name checks on one SHA (with a cancelled duplicate) block Rulesets merging. Do not merge failed CI.
- Publish GHCR images **only after the matching main SHA's CI succeeds**; deployments remain pinned to a tested SHA. Never deploy by bypassing tests.
- After each successful netcup deployment, run the complete Playwright suite again against **https://pdf.plainmile.com** inside the SAME ephemeral GitHub-hosted deployment runner. Download actual exported PDFs and inspect them; route/health-only checks are insufficient.
- Public HTTPS QA may retry each failed browser test **once** in a fresh context for transient network/worker failures, with a finite 15-minute step limit. Never skip failed tests or replace full public PDF/SEO coverage with smoke checks; repeatable failure must roll back the deployment. Pre-merge Docker CI retains zero retries. Log visible retries and keep diagnostics for unresolved failures.
- GitHub public standard hosted runners are ephemeral. Use `docker run --rm`, `if: always()` cleanup, finite job timeouts, concurrency to cancel superseded PR CI, and avoid duplicate public QA workflows. Retain screenshots/traces only when tests fail (one day).
- The manual Public Site Browser E2E workflow is for requested audits, not a second automatic runner job after deployment. Never leave a persistent VPS QA container or send customer files to CI; synthetic PDFs only.

## New browser-local conversion tools and open-source license

- MIT License: keep `LICENSE` and public GitHub link visible in the bilingual footer; do not add proprietary or incompatible assets.
- PDF to JPG/PNG must verify image signatures and page selection; multi-page exports are a ZIP. PDF compression uses optional rasterization and must show measured input/output bytes; do not claim lossless compression or download files that grow larger. Warn users about text, links, annotations, forms and signatures being rasterized/lost.
- PDF-to-TXT/Markdown extracts only existing selectable text, never claim OCR or precise original layout. Markdown heading conversion is heuristic. TXT/Markdown-to-PDF supports a limited Markdown subset; non-Latin scripts rendered using local browser fonts yield image-based, not searchable, PDF pages.
- New image formats must have strict compressed-header dimension checks before canvas decoding, preserving 36-megapixel limits. Support only BMP and static AVIF when the browser decoder can handle them; reject animated AVIF/WebP rather than quietly discarding frames. Provide meaningful errors on unsupported browsers, and test real BMP and generated AVIF fixtures, PNG-backed exported PDF pixel dimensions and Chinese narrow screens. Do not imply HEIC, TIFF or dynamic-image conversion.\n- Keep input/resource limits, no upload network calls, bilingual SEO routes and end-to-end checks of exported files for every new tool. E2E gate before each publish and public GitHub Runner E2E after each netcup deployment. Clean QA containers even on failure.

## Book-length PDF limits (2026-10)

- Avoid one arbitrary 25 MiB/50-page limit for all tools. Set and show mode-specific safeguards: PDF text extraction/numbering 100 MiB and 1,000 pages; PDF-to-images max 60 selected pages per export with page-range batching and 12 MP/canvas; lossy compression 120 pages; TXT/Markdown input 5 MiB with 1,000 output pages for Latin and 300 image-based output pages for CJK; workspace up to 100 MiB/file, 200 MiB total and 600 pages with lazy thumbnail rendering.
- These are *ceilings*, not performance guarantees. Favor per-page cleanup, explicit worker teardown, a visible progress indication, and clearly localized warnings. Keep generated ZIP size bounded.
- Every-N splitting (including N=1) must use explicit batches of up to 50 output PDFs whenever the output count exceeds 50, with unique output page-range filenames, previous/next controls, and no automatic multiple downloads.
- Existing PDF chapter bookmark splitting supports explicitly chosen PDF.js outline depth 1/2/3 ONLY on a single original file with complete unchanged page order. Bound nested traversal, ignore invalid destinations, do not silently fall back to a different depth, and never invent chapters for OCR/scans. ZIP chapter names are optional **off by default**, sanitize path/device characters, ordinal-prefix all entries, and reset on manual ranges, changed level/source or page edits; generated PDFs still lose original clickable bookmarks. Unit and real nested PDF browser E2E must check exact pages and safe ZIP entries.
- A one-output batch downloads directly as PDF. A partial batch never clears unsaved-document warnings. Preserve the 50-output / 128 MiB per-download limits and test real first/middle/last batch PDFs, incomplete final chunks, Undo/Redo and blank insertion.
- Split progress must count actual copied OUTPUT pages (including intentional duplicate/overlapping ranges), not merely completed output files or original input pages. Report cumulative pages across a batch or odd/even pair from composePdf callbacks, retain a separate localized ZIP packaging phase and native accessible progress indicator, and never count cancellation or an unfinished ZIP as a completed download. Test real long-document page-level progress, partial-batch totals, and cancellation.
- Bookmark-assisted chapter splitting uses only TOP-LEVEL document-outline destinations from a single unchanged-order complete PDF (page rotation allowed). Resolve using the local cached PDF.js document, never transfer outlines or source text, show the EXACT complete proposed page ranges before editing and note that output PDFs do not retain original clickable bookmarks, preserve any handwritten ranges unless the user confirms replacement, reject invalid/missing/over-50 output plans, and disable after page reorder/delete/duplicate/merge. Map chapter starts to cuts before each chapter and keep cover pages. Verify real PDFs and 375px bilingual UI; never claim OCR-based or automatic text-based chapter detection.
- Odd/even splitting uses CURRENT one-based output page positions, producing two PDFs in one ZIP only when at least 2 pages exist. Partition all pages exactly once even after drag/reorder; never interpret printed/source page labels as parity. Reuse the guarded ZIP/export pipeline and check real output PDF order, metadata cautions, 128 MiB budget and cancellation. Manual comma-separated ranges still mean one PDF per range; link users seeking a single combined PDF to Extract Pages without pretending source files transfer between tools.
- Track split-batch download requests (not verified disk saves) only in ephemeral React state, scoped to the exact document revision and chunk-size plan. Show unrequested batches, allow jumping to a missing batch, reset on document edits and plan changes. Visual split page-jump must focus the correct current output page without changing cuts, selections or page order; test Chinese 375px screens.
- Text extraction groups PDF.js positioned fragments by Y-baseline. Keep the historical first-created matching-row rule, row tolerance, X sorting and rotated/multi-column reading order. Benchmark dense text and compare indexed results against the original linear reference; never silently lose text for unusual coordinate/font data.
- Unit and public Playwright E2E must verify a synthetic 320+ page PDF (text first+last, numbered PDF, late-page raster selection), boundary rejection, and old workspace PDF behavior. Never claim 500-page memory safety without testing a representative input. No customer data in CI.

## Human-first UI and technical SEO safeguards

- Prefer modest typography, crisp office-style surfaces, practical grouped tools and clear primary actions over gradients, fictional success metrics, stock illustrations or AI-marketing copy.
- The static HTML catalog must render all 16 genuine tools (four intuitive categories) even when JavaScript is unavailable. Search only filters the already-visible HTML; keep keyboard, mobile and bilingual labels usable.
- Every real tool page must provide a localized, visible `<noscript>` explanation when its client-only React editor cannot run. Keep indexable titles, descriptions, how-to content, real FAQs and internal links prerendered in HTML; never turn blank JS islands into soft 404s or claim editing works without JavaScript.
- On phone-width layouts, editable search, page-range, file-name and converter text/select controls must compute to at least 16px to prevent involuntary iOS Safari input-focus zoom. Keep pinch zoom enabled, native file pickers/checkboxes untouched, desktop typography unchanged, and verify 375px screens do not overflow.
- Page-specific useful answers must be true to current implementations, including page limits, rasterized/uncopyable Unicode PDF text and lossy PDF compression. Avoid overclaiming or duplicating generic copy.
- The dedicated Extract Pages route should expose its typed-range panel after importing a PDF, without an extra hidden disclosure click. Invalid/reversed/out-of-bound ranges must show a localized inline error and must never enable the combined-PDF export; successful edits recover the preview and action. Keep the checkbox selection independent and preserve exact typed order/first-occurrence de-duplication. Validate with real downloaded PDF bytes and mobile E2E.
- Keep SEO canonical and reciprocal EN/zh-CN hreflang, sitemap/robots, unique titles and descriptions, one H1 and accurate visible JSON-LD (WebSite, WebApplication, BreadcrumbList) in both languages. Do not add Review/FAQPage rich-result markup unless genuine eligibility and content permit it.
- The Extract PDF Pages tool has TWO distinct, visible paths: checkbox selection exports pages in current workspace order; directly combining typed page ranges exports one PDF in entered range order, deduplicating overlaps on first occurrence. Keep selection/history/original pages untouched, validate all ranges before export, support fullwidth Chinese input and mobile screens, and prove actual downloaded PDF contents via E2E. Split PDF custom ranges still produce separate PDFs/ZIP: never silently reuse the combined-extract meaning there. - Every feature or UI PR must pass unit, container-build and full Playwright E2E before merge; every production deploy runs actual public-site tests on the same Runner and cleans Docker resources. Don't add redundant scheduled QA workflows.
